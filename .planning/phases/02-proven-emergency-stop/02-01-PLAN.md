```sh
#!/bin/sh
# STOP-06: 100 percent branch coverage of crates/stop, and nothing else (D-53).
#
# Branch coverage is not available on the toolchain rust-toolchain.toml pins. cargo-llvm-cov's
# own README states the flag "requires nightly", the underlying -Z coverage-options=branch is an
# unstable compiler flag, and cargo-tarpaulin's help reads "Branch coverage: NOT IMPLEMENTED", so
# tarpaulin cannot do it at any toolchain. D-57 resolves this by pinning a dated nightly for this
# command alone; every other job in CI stays on stable.
#
# The threshold is NOT enforced with --fail-under-branches. It is enforced by reading the JSON
# export, because that same read is what makes the gate non-vacuous: a coverage run that
# instrumented nothing reports no uncovered branches and would satisfy any percentage threshold
# while proving nothing at all.
set -eu

NIGHTLY=nightly-2026-08-01   # replace with the date this task actually settled on
OUT=$(mktemp -t nr-coverage.XXXXXX)
trap 'rm -f "$OUT"' EXIT

cargo "+$NIGHTLY" llvm-cov --branch -p nr-stop \
    --ignore-filename-regex '(^|/)crates/stop/tests/' \
    --json --output-path "$OUT"

python3 - "$OUT" <<'PY'
import json, pathlib, sys

report = json.load(open(sys.argv[1]))
data = report["data"][0]
totals = data["totals"]
branches = totals["branches"]

src = sorted(p.name for p in pathlib.Path("crates/stop/src").glob("*.rs"))
covered_files = sorted({pathlib.Path(f["filename"]).name for f in data["files"]})
missing = [name for name in src if name not in covered_files]

problems = []
if missing:
    problems.append("not instrumented: " + ", ".join(missing))
if branches["count"] == 0:
    problems.append("the report contains zero branches; the gate would pass vacuously")
if branches["covered"] != branches["count"]:
    problems.append(
        "%d of %d branches uncovered" % (branches["count"] - branches["covered"], branches["count"])
    )
    for f in data["files"]:
        fb = f["summary"]["branches"]
        if fb["covered"] != fb["count"]:
            problems.append("  %s: %d of %d" % (f["filename"], fb["covered"], fb["count"]))

print("branches %d/%d  regions %d/%d  lines %d/%d" % (
    branches["covered"], branches["count"],
    totals["regions"]["covered"], totals["regions"]["count"],
    totals["lines"]["covered"], totals["lines"]["count"],
))

if problems:
    for p in problems:
        print("nr-coverage.sh: " + p, file=sys.stderr)
    sys.exit(1)
PY
```

Two notes on that script, both deliberate. Regions and lines are printed and not gated on:

file that fails to be instrumented at all disappears from the report rather than showing as zero,
which is the exact failure mode a percentage threshold cannot see.

<threat_model>
## Trust boundaries

This plan installs two external toolchains and commits a script that will become a blocking CI
gate. There is no network input, no user input, no authentication and no persistence beyond
committed files. The boundaries that exist are supply-chain and integrity shaped.

| Boundary | Description |
|----------|-------------|
| crates.io and the Kani release bucket -> this machine | `cargo install` and `cargo kani setup` fetch and execute third-party code, and `cargo kani setup` fetches a whole compiler outside cargo's own integrity checks. |
| a tool's observed behaviour -> a gate that later blocks merges | What this plan records about Kani's and llvm-cov's output becomes the literal grep strings a blocking check depends on. |
| the pinned nightly -> every published coverage claim | A moving toolchain would silently change what "100 percent branch coverage" measured. |

## STRIDE threat register

| Threat ID | Category | Component | Disposition | Mitigation plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Tampering | `cargo install kani-verifier` | mitigate | `--locked` plus an exact version (`@0.67.0`) so the resolved dependency graph is the one the publisher locked, not whatever resolves today. A version substitution is only allowed with the exact failure and the replacement recorded in the SUMMARY (D-51). |
| T-2-02 | Tampering | `cargo kani setup`'s download into `~/.kani` | accept | The download is unsigned and outside cargo's integrity path, and Kani offers no alternative install for the proof this phase is built on. Accepted rather than mitigated because the only real mitigation is not adopting Kani. Scope is bounded: it installs into `~/.kani`, changes no rustup toolchain, and the task verifies `rust-toolchain.toml` is byte-identical afterwards. |
