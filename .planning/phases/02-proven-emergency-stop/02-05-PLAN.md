Write `docs/proofs/phase-6-output-gate-contract.md`. It is the written half of D-45: the modelled
consumer is shipped code, and this is what a real consumer must not do if the STOP-03 guarantee is
to survive into Phase 6.

Write it as a contract addressed to whoever builds the Phase 6 decoder and sink, not as a summary
of Phase 2. Sections, sentence case headings:

`What this contract is`. STOP-03 is proved at FSM level against `ModelledConsumer`, which takes
permits and emits nothing. The proof establishes that no permit exists outside `Running`. It does
not and cannot establish that a future consumer uses permits the way the model does. This document
names the difference.

`What the type system already enforces`. List what Phase 6 gets for free, each item naming the
mechanism rather than asserting the property:

  - `OutputPermit` has a private field and no public constructor, so it cannot be forged from
    outside `nr-stop`.
  - It is neither `Clone` nor `Copy`, so one permit cannot become two.
  - `ModelledConsumer::emit` takes it by value, so using it consumes it.
  - There is no method anywhere in `nr-stop` that emits without one.
  - `EmergencyStop` has no reset, restart or rearm, so a stopped session cannot be reopened; a new
    session means a new `EmergencyStop` value.

`Obligations on the real consumer`. The rules Phase 6 must follow, each with the failure it
prevents stated concretely. At minimum:

  1. Do not cache a permit across iterations. Acquire it inside the iteration that uses it and let
     it be consumed there. A permit held from a previous iteration is a permit issued while the
     machine was `Running` and used after it stopped, which is exactly the output STOP-03 forbids.
     Note that `OutputPermit` is not `Copy` and is consumed by value, so the natural way to write
     this is already correct and caching one requires deliberate effort, for example storing it in
     a struct field or in an `Option`.
  2. Do not emit without one. Every path that produces output must take an `OutputPermit` by
     value. A convenience path that skips the permit, for a retry, a flush, a test, or an error
     path, deletes the guarantee for every path, because the guarantee is that no such path exists.
  3. Do not add a public constructor to `OutputPermit`, and do not add a `Clone` or `Copy` derive
     to it, for any reason including making a test easier to write.
  4. Poll the gate at one fixed point per node iteration (D-32), and treat any state other than
     `Running` as closed. Do not branch on `Stopping` versus `Stopped`: the permit supply closes at
     the abort, and treating `Stopping` as still-open is the single most likely way to break this.
  5. Raise `acknowledge` when the gate is first observed closed, and understand what it is for. It
     ends the interval STOP-07 measures. It does not make the system safe, and the system does not
     wait for it: the permit supply already closed at the abort (D-40). A consumer that never
     acknowledges is safe and unmeasured, which is the correct trade if it ever comes up.

`What would tell us this contract was broken`. Concretely: a Phase 6 test that emits after a stop;
a grep for `OutputPermit` in a struct field or a long-lived `Option`; any `pub fn` returning an
`OutputPermit` outside `nr-stop`; any output path whose signature does not consume one. Say that
these are the checks a Phase 6 reviewer should run, so this document is actionable rather than
advisory.

`What this contract does not cover`. Thread interleavings, which are unverified until Phase 4's
loom work, and timing, which is STOP-07. Point at
`docs/proofs/emergency-stop-proof-scope.md` rather than restating it.

Prose style as everywhere else: no em dashes, ASCII only, no emoji, sentence case headings.

## Trust boundaries

This plan writes claims, not code. Its threats are about a reader believing something the evidence
does not support, and about a future phase inheriting a guarantee it then breaks without noticing.
There is no network surface, no input and no secret here.

| Boundary | Description |
|----------|-------------|
| a solver run -> a published sentence | A reader will act on the sentence and will not re-run the solver. |
| Phase 2 -> Phase 6 | A proved property crosses a phase boundary only as a written obligation, because no type can enforce it there. |
| an automated check -> an honest claim | Every mechanical property of these documents is checkable; whether they are honest is not, which is why this plan has a human gate. |
