unit that takes the run with no login session, and the CI workflow that compares the result
against a reviewed baseline.

Purpose: BENCH-08 asks for a CI job that commits a weekly metrics JSON carrying p50, p95 and p99
for every stage instrumented so far. D-05 puts the measurement on a systemd oneshot plus timer
with no login session, which satisfies PLAT-02 by construction rather than by discipline, and

exists to eliminate. D-11 puts the regression judgement in reviewable CI config rather than in a
script on one laptop, so a failure is visible without logging into the rig. D-08 makes a missed
week a recorded gap rather than a backfilled run, because a post-boot catch-up would be a
measurably different environment.

the baseline it compares against is seeded from the PLAT-03 headline run in plan 01-13, which is
the first run measured under the finished protocol and therefore the first defensible baseline.

This is the one plan of the phase's final five that needs no rig access. It authors the series
command, the unit files, the workflow and the seeded baseline, all on the dev host. Installing the
units on the rig and watching the first timer fire is plan 01-15, which is the runbook.

Argument surface:

```
nrmeasure series
  --measurements <path>   default ./measurements
  --metrics <path>        default ./metrics
  --append                scan run directories and append any not yet in the series
  --compare               compare every entry against metrics/baseline.json and print verdicts
  --record-refusal <check>  record the current ISO week as a gap caused by a precondition refusal
  --seed-baseline <run-id>  write the given run's entries into metrics/baseline.json entries
```

`--append` walks `measurements/`, loads each `manifest.json`, and for each capture in
`artifacts` produces one `StageMetrics`:

  a cyclictest `.hist` artifact  -> stage `cyclictest.wakeup_latency`
  an hwlatdetect text artifact   -> stage `hwlatdetect.firmware_gap`

Percentiles come from `nr_histogram`'s overflow-inclusive path. For hwlatdetect, whose output is a
list of events rather than a histogram, record `max_us` from the reported maximum and set the
percentile fields from the event list; if the output does not support a percentile, record the
field as the maximum and state that convention in the module doc comment. Do not silently report a
percentile the tool did not provide.

Two exclusions, both load-bearing:

  1. A run whose `instrument_class` is `investigation` is never appended. RESEARCH.md pattern 2
     is explicit that investigation runs carry tracer overhead and must never feed the regression
     series. Print the skipped run ids so the exclusion is visible rather than silent.
  2. A run whose `excluded_from_series` is true is appended with `excluded_from_series: true` and
     its reason carried through, so it appears in the record but is skipped by `--compare`. This
     is the BENCH-06 half: the losing run is in the file, it just does not move the baseline.

`--append` also calls `record_gaps` against `metrics/coverage.json` before writing, so a machine
that was off for two weeks produces two gap entries and not a silent hole. D-08 forbids backfill,
and `series_never_backfills` is the test that keeps it forbidden.

`--compare` reads `metrics/baseline.json`, calls `nr_metrics::baseline::compare` for every entry
not excluded from the series, and prints one line per entry. Exit code 1 only when at least one
verdict is `Fail`. `NoComparableBaseline`, `SkippedContaminated` and `SkippedUncalibrated` print
their reason and exit 0, because none of them is a regression and treating them as one would
train the operator to ignore the check.

`--seed-baseline <run-id>` copies that run's entries into `metrics/baseline.json`'s `entries`
array, keyed by (rig_slug, run_class, stage). It refuses when the named run is excluded from the
series, contaminated, or of `instrument_class` investigation. A baseline seeded from a
contaminated run would silently license every future regression.

Test function names must be exactly `series_append_adds_one_entry_per_stage`,
`series_skips_investigation_runs`, `series_skips_already_recorded`,
`series_records_gap_for_missed_weeks`, `series_records_gap_for_refused_run`,
`series_never_backfills`, `series_compare_reports_verdict` and
`series_compare_neutral_on_no_baseline`. Drive them with `assert_cmd` against temporary trees
built from the committed fixtures, not against the real `measurements/`.

`deploy/systemd/neurorust-measure.service`:

```ini
[Unit]
Description=neurorust weekly measurement run
Documentation=file:///opt/neurorust/docs/measurement-protocol.md
After=multi-user.target
ConditionPathExists=/opt/neurorust/target/release/nrmeasure

[Service]
Type=oneshot
User=root
WorkingDirectory=/opt/neurorust
ExecStart=/opt/neurorust/deploy/systemd/neurorust-weekly-run.sh
TimeoutStartSec=3h
StandardOutput=journal
StandardError=journal
# The measurement needs these; nothing else.
CapabilityBoundingSet=CAP_SYS_NICE CAP_IPC_LOCK CAP_SYS_ADMIN CAP_DAC_OVERRIDE
NoNewPrivileges=false
ProtectHome=false
PrivateTmp=false
```

`PrivateTmp` and `ProtectHome` are off deliberately: the run writes into the repository working
tree and reads the real `/sys` and `/proc`. State that in a comment. Do not add sandboxing that
would change the environment being measured; the harness is measuring this machine and a
namespace between it and the machine is a measurement error.

`deploy/systemd/neurorust-measure.timer`:

```ini
[Unit]
Description=neurorust weekly measurement trigger

[Timer]
OnCalendar=Sun *-*-* 03:00:00
# D-08: a missed week is a recorded gap, never a backfill. Persistent=true would fire a
# catch-up run at the next boot, which would be a measurably different environment and would
# silently fill a hole that should stay visible in metrics/coverage.json.
Persistent=false
AccuracySec=1min
RandomizedDelaySec=0

[Install]
WantedBy=timers.target
```

`RandomizedDelaySec=0` because a randomised start would vary the thermal and idle state the run
begins in, and `ThermalHeadroomAtStart` is one of the 14 assertions.

`deploy/systemd/neurorust-weekly-run.sh`, POSIX shell, `set -eu`, ASCII only:

```sh
#!/bin/sh
set -eu

REPO=/opt/neurorust
BIN="$REPO/target/release/nrmeasure"
RIG=precision3591
TOKEN_FILE=/etc/neurorust/push-token

cd "$REPO"

# D-09: the weekly watch covers both cyclictest and hwlatdetect, because a fwupd BIOS or
# microcode update could silently move the firmware floor every later figure sits on.
# D-10: roughly one hour for the regression series.
if ! "$BIN" run --rig-slug "$RIG" --class weekly --instrument headline-series \
        --cpus 6-11 --main-cpus 0,1 \
        --duration 3600 --interval 200 --histogram-max 400 --priority 99 \
        --with-hwlatdetect --hwlatdetect-duration 900 \
        --measurements-root "$REPO/measurements" \
        --note "Weekly regression run, unattended, systemd oneshot with no login session."; then
    # D-06 plus D-08: a run refused on a precondition produces the same recorded gap as a
    # missed week. It does not produce a retry.
    "$BIN" series --record-refusal "$(cat /run/nrmeasure-refusal 2>/dev/null || echo unknown)"
    git add metrics/coverage.json
    git -c user.name=neurorust-rig -c user.email=rig@localhost \
        commit -m "metrics: record coverage gap for refused weekly run"
    git push origin HEAD:refs/heads/main
    exit 0
fi

"$BIN" verify --write-index
"$BIN" verify --strict --check-index
"$BIN" series --append

# D-07: the weekly p50/p95/p99 JSON is a regression-tracking artifact and auto-commits.
# Anything that becomes a published claim reaches main only through a reviewed commit, so this
# script never touches docs/ and never edits metrics/baseline.json.
git add measurements metrics/latency-series.json metrics/coverage.json measurements/INDEX.md
git -c user.name=neurorust-rig -c user.email=rig@localhost \
    commit -m "metrics: weekly run $(date -u +%Y-%m-%d)"

GIT_ASKPASS=/bin/true git -c credential.helper="!f(){ echo username=x-access-token; echo password=$(cat $TOKEN_FILE); };f" \
    push origin HEAD:refs/heads/main
```

The credential helper reads the token from a root-owned file rather than embedding it in the unit
or the environment, so it does not appear in `systemctl show`, in the journal, or in `ps`. State
that in a comment.

The headline run is a `headline`-class run and the weekly runs are `weekly`-class, and
`nr_metrics::baseline::compare` matches on (rig_slug, run_class, stage). Seeding only the headline

and the choice must be recorded:

  a. Seed the `headline` entry now, and let the first weekly run seed the `weekly` entry in a
     separate reviewed commit once it exists. Until then weekly runs report
     `NoComparableBaseline`, which is neutral and exits 0. This is the correct answer: a baseline
     for a run class that has never been measured would be fabricated.
  b. Copy the headline figures into a `weekly` entry. Rejected: a four hour run and a one hour run
     have different worst-case exposure, and D-10 tags run classes precisely so they are never
     averaged together.

`docs/publication-layout.md` that the weekly baseline is seeded after the first weekly run.

Then write `.github/workflows/regression.yml`:

```yaml
name: regression

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read

concurrency:
  group: regression-${{ github.ref }}
  cancel-in-progress: true

jobs:
  regression:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2

      # T-1-04: the baseline must not move in the same push as the run being compared against
      # it. Compare the baseline at the merge base, not at the pushed head.
      - name: The baseline and the series did not change together
        run: |
          base=$(git merge-base origin/main HEAD)
          changed=$(git diff --name-only "$base" HEAD)
          if echo "$changed" | grep -q '^metrics/baseline.json$' \
             && echo "$changed" | grep -q '^metrics/latency-series.json$'; then
            echo "metrics/baseline.json and metrics/latency-series.json changed in the same push."
            echo "Moving the baseline in the same commit as the run it is compared against"
            echo "defeats the regression gate. Split them into two commits."
            exit 1
          fi

      - name: Compare against the reviewed baseline
        run: |
          base=$(git merge-base origin/main HEAD)
          git show "$base:metrics/baseline.json" > /tmp/baseline-at-merge-base.json
          cargo build -p nr-cli --release
          ./target/release/nrmeasure series --compare --baseline /tmp/baseline-at-merge-base.json
```

If `series --compare` does not yet accept a `--baseline <path>` override, add it in task 1 and
note the addition. Reading the baseline from the merge base rather than from the working tree is
what makes the gate resistant to being moved.

Two properties that must not be weakened:

  The workflow token is read-only. The rig pushes with its own credential; CI only judges. D-11
  says the rig measures and pushes and a GitHub Actions workflow compares, so a CI job with write
  access would blur that split.

  A regressed run is never withheld. D-11 is explicit that the harness never withholds a regressed
  run, because a bad run is evidence under BENCH-06. The gate fails the check; it does not revert
  the commit, does not delete the run, and does not filter it from the series. The failing check
  is the signal, and the evidence stays published.

Also commit the initial `metrics/latency-series.json` and `metrics/coverage.json` produced by
`series --append`, so the files exist with real content and the weekly job appends rather than
creating.

## Trust boundaries

| Boundary | Description |
|----------|-------------|

| Threat ID | Category | Component | Disposition | Mitigation plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Elevation of privilege | deploy/systemd/neurorust-weekly-run.sh, /etc/neurorust/push-token | mitigate | The push credential is a fine-grained token scoped to this repository only, contents write only, with an expiry. It lives in a root-owned file at mode 0600, is read through a credential helper rather than an environment variable so it does not appear in `systemctl show`, the journal or `ps`, and `install.sh` refuses to install if the file is absent or wrongly permissioned. Creating the token with the correct scope is a human action in plan 01-15. |
| T-1-04 | Tampering | .github/workflows/regression.yml | mitigate | The comparison reads `metrics/baseline.json` at the merge base rather than at the pushed head, and a dedicated step fails the check when the baseline and the series change in the same push. Moving the baseline to make a regression pass therefore requires two commits, the first of which is a visible, reviewable baseline change. |
| T-1-11 | Elevation of privilege | .github/workflows/regression.yml | mitigate | `permissions: contents: read` and no secrets. CI judges and never writes, preserving D-11's split where the rig measures and pushes and CI compares. |
| T-1-20 | Tampering | crates/cli/src/cmd/series.rs | mitigate | `--append` skips any run whose `instrument_class` is `investigation` and prints the skipped ids, so tracer-inflated numbers cannot enter the regression series. `--seed-baseline` additionally refuses a contaminated, excluded, or investigation run, so a bad baseline cannot silently license every future regression. |
| T-1-40 | Tampering | deploy/systemd/neurorust-weekly-run.sh | mitigate | The wrapper auto-commits only `measurements/`, `metrics/latency-series.json`, `metrics/coverage.json` and `measurements/INDEX.md`. This is D-07's split enforced by the script's own scope. |
| T-1-41 | Denial of service | neurorust-measure.timer | accept | The timer holds the machine for roughly 75 minutes every Sunday at 03:00, and the rig is also a Windows machine. Accepted; `deploy/systemd/README.md` documents how to disable the timer before using the machine, and D-08 means a disabled week is recorded as a gap rather than lost. |
