Purpose: BENCH-08 asks for a CI job that commits a weekly metrics JSON carrying p50, p95 and p99

with no login session, which satisfies PLAT-02 by construction rather than by discipline. D-11
puts the regression judgement in reviewable CI config rather than in a script on one laptop.
D-08 makes a missed week a recorded gap rather than a backfilled run.

**Two defects this plan was rewritten to remove**, both found by the external audit before any of
it was implemented.

The first: the earlier version instructed unavailable firmware percentiles to be filled with the
maximum, with a module comment explaining the convention. A comment does not make those valid
percentiles. Percentiles of threshold-exceeding records are not percentiles of all sampling
windows, and neither is a percentile of scheduling wakeups. A statistic the instrument did not
produce is recorded as null, with the population it would have been over named explicitly.

The second: the earlier regression workflow computed `git merge-base origin/main HEAD` for both
the pull-request and the push case. On a push to main, `origin/main` and `HEAD` are the same
commit, the merge base is that commit, the diff against it is empty, and the guard that exists to
stop the baseline moving in the same push as the run lets exactly that through. The guard must use
the base revision belonging to the event: the pull request's own base sha, or the branch's
previous head on a push. External audit finding 10.

D-03 puts the weekly job last, and this plan is late in the wave order for a real dependency
reason as well: the baseline it compares against is seeded from the PLAT-03 headline run in plan
01-13, which is the first run measured under the finished protocol and therefore the first
defensible baseline.

This is the one plan of the phase's final stretch that needs no rig access. It authors the series
command, the unit files, the workflow and the seeded baseline, all on the dev host. Installing the
units on the rig and watching the first timer fire is plan 01-15.

Output: `nrmeasure series`, version-controlled systemd units, a regression workflow with an
event-specific base revision, and a seeded baseline.

    /// Null when the instrument does not produce this statistic. Never substituted.
    ///
    /// A firmware screen reports threshold-exceeding records, not a distribution over
    /// sampling windows, so it has a maximum and a count and no percentiles at all. Filling
    /// these with the maximum was the earlier instruction here; it produced four numbers
    /// that look like a distribution and are not one. Finding 10 of `01-EXTERNAL-AUDIT.md`.
    pub p50_us: Option<u64>,
    pub p95_us: Option<u64>,
    pub p99_us: Option<u64>,
    pub p999_us: Option<u64>,

    /// reader never has to guess. For cyclictest: `scheduling wakeups, binned samples plus
    /// overflows`. For rtla hwnoise: `hardware noise reported per CPU over the sampling

**Then the subcommand.** Argument surface:

```
nrmeasure series
  --measurements <path>     default ./measurements
  --metrics <path>          default ./metrics
  --append                  scan run directories and append any not yet in the series
  --compare                 compare every entry against the baseline and print verdicts
  --baseline <path>         override the baseline path (CI reads it from a base revision)
  --record-refusal <check>  record the current ISO week as a gap caused by a precondition refusal
  --seed-baseline <run-id>  write the given run's entries into metrics/baseline.json entries
```

`--append` walks `measurements/`, loads each `manifest.json`, and for each capture produces one
`StageMetrics`:

  a cyclictest `.hist` artifact      -> stage `cyclictest.wakeup_latency`,
                                        percentiles from `nr_histogram`'s overflow-inclusive path,
                                        population `scheduling wakeups, binned samples plus overflows`
  an `rtla-hwnoise` artifact         -> stage `rtla_hwnoise.hardware_noise`,
                                        `max_us` and `sample_count` from the parsed run,
                                        all four percentile fields null,
                                        population `hardware noise reported per CPU over the sampling window`
  `smi_counts` present in the manifest -> stage `smi.count`, `max_us` the largest per-CPU delta,
                                        percentiles null,
                                        population `SMI count per isolated CPU over the run`

The `smi.count` stage is worth having because D-09's reason for the weekly firmware watch is that
a fwupd BIOS or microcode update could silently move the floor every later figure sits on, and an
exact SMI count is the cheapest possible detector for that.

Three exclusions, all load-bearing:

  1. A run whose `instrument_class` is `investigation` is never appended. RESEARCH.md pattern 2
     is explicit that investigation runs carry tracer overhead and must never feed the regression
     series. Print the skipped run ids so the exclusion is visible rather than silent.
  2. A directory holding only an `ATTEMPT.json` (plan 01-17's failed attempt) is never appended.
     Print it as skipped with its failure stage. It is already in `measurements/INDEX.md`, which
     is where BENCH-06 requires it to appear.
  3. A run whose `excluded_from_series` is true IS appended, with `excluded_from_series: true`
     and its reason carried through, so it appears in the record but is skipped by `--compare`.
     That is the other half of BENCH-06: the losing run is in the file, it just does not move the
     baseline.

`--append` calls `record_gaps` against `metrics/coverage.json` before writing, so a machine that
was off for two weeks produces two gap entries and not a silent hole. D-08 forbids backfill and
`series_never_backfills` is the test that keeps it forbidden.

`--compare` reads the baseline from `--baseline` when given and `metrics/baseline.json` otherwise,
calls `compare` for every entry not excluded from the series, and prints one line per entry. Exit
code 1 only when at least one verdict is `Fail`. `NoComparableBaseline`, `SkippedContaminated`,
`SkippedUncalibrated` and `SkippedNoStatistic` print their reason and exit 0, because none is a
regression and treating them as one would train the operator to ignore the check.

`--seed-baseline <run-id>` copies that run's entries into `metrics/baseline.json`'s `entries`
array, keyed by (rig_slug, run_class, stage). It refuses when the named run is excluded from the
series, contaminated, or of `instrument_class` investigation. A baseline seeded from a
contaminated run would silently license every future regression. It also refuses to write a
baseline entry for a stage whose `p99_us` is null, because a threshold on a statistic that does
not exist can never fire.

`deploy/systemd/neurorust-measure.service`:

```ini
[Unit]
Description=neurorust weekly measurement run
Documentation=file:///opt/neurorust/docs/measurement-protocol.md
After=multi-user.target
ConditionPathExists=/opt/neurorust/target/release/nrmeasure
# The interactive entry point (scripts/nr-run-measurement) launches a transient unit named
# nr-measurement. Two captures at once contaminate each other, so refuse to start while
# that one is active.
Conflicts=nr-measurement.service

[Service]
Type=oneshot
User=root
WorkingDirectory=/opt/neurorust
ExecStart=/opt/neurorust/deploy/systemd/neurorust-weekly-run.sh
# TimeoutStartSec, not RuntimeMaxSec. On a Type=oneshot unit the whole run is the start
# phase, and systemd ignores RuntimeMaxSec entirely, printing "RuntimeMaxSec= has no effect
# in combination with Type=oneshot. Ignoring." into the journal. That line is the only
# reason the defect was found. Check for its absence after any change here.
TimeoutStartSec=3h
StandardOutput=journal
StandardError=journal
# The measurement needs these; nothing else.
CapabilityBoundingSet=CAP_SYS_NICE CAP_IPC_LOCK CAP_SYS_ADMIN CAP_DAC_OVERRIDE CAP_SYS_RAWIO
NoNewPrivileges=false
ProtectHome=false
PrivateTmp=false
```

`CAP_SYS_RAWIO` is new and is there for `rdmsr`, which reads `/dev/cpu/*/msr`. Without it the
weekly run records `smi_counts` as unavailable every week.

`PrivateTmp` and `ProtectHome` are off deliberately: the run writes into the repository working
tree and reads the real `/sys` and `/proc`. State that in a comment. Do not add sandboxing that
would change the environment being measured; a namespace between the harness and the machine is a
measurement error.

`deploy/systemd/neurorust-measure.timer`:

```ini
[Unit]
Description=neurorust weekly measurement trigger

[Timer]
OnCalendar=Sun *-*-* 03:00:00
# D-08: a missed week is a recorded gap, never a backfill. Persistent=true would fire a
# catch-up run at the next boot, which would be a measurably different environment and would
# silently fill a hole that should stay visible in metrics/coverage.json.

[Install]
WantedBy=timers.target
```

`RandomizedDelaySec=0` because a randomised start would vary the thermal and idle state the run
begins in, and `ThermalHeadroomAtStart` is one of the fifteen assertions.

`deploy/systemd/neurorust-weekly-run.sh`, POSIX shell, `set -eu`, ASCII only:

```sh
#!/bin/sh
set -eu

PATH=/usr/sbin:/usr/bin:/sbin:/bin
export PATH

REPO=/opt/neurorust
BIN="$REPO/target/release/nrmeasure"
RIG=precision3591
TOKEN_FILE=/etc/neurorust/push-token
export TOKEN_FILE

cd "$REPO"

# One push path, used by both the refusal branch and the success branch, so neither can
# drift from the other. The credential helper is in SINGLE quotes on purpose: in double
# quotes this shell expands $(cat "$TOKEN_FILE") before git ever runs, which puts the token
# itself into git's argv where any user on the machine can read it out of ps. Single quotes
# leave the substitution for the shell git spawns to run the helper, which is why TOKEN_FILE
# is exported above. GIT_ASKPASS=/bin/true stops git falling back to a prompt if the helper
# returns nothing, rather than hanging an unattended unit forever.
push_to_origin() {
    GIT_ASKPASS=/bin/true git \
        -c credential.helper='!f(){ echo username=x-access-token; echo "password=$(cat "$TOKEN_FILE")"; };f' \
        push origin HEAD:refs/heads/main
}

# D-09: the weekly watch covers scheduling latency and the firmware floor, because a fwupd
# BIOS or microcode update could silently move the floor every later figure sits on.
# The firmware instrument is rtla hwnoise, not hwlatdetect: hwlatdetect's tracer runs a
# single non-migrating thread that isolcpus keeps off CPUs 6-11 entirely, so it cannot
# watch the cores this project cares about. See docs/rig/firmware-floor-rt-vs-stock.md.
# D-10: roughly one hour of cyclictest for the regression series.
if ! "$BIN" run --rig-slug "$RIG" --class weekly --instrument headline-series \
        --cpus 6-11 --main-cpus 0,1 \
        --duration 3600 --interval 200 --histogram-max 400 --priority 99 \
        --with-hwnoise --hwnoise-cpus 6-11 --hwnoise-housekeeping 0-5 \
        --hwnoise-duration 900 --hwnoise-priority f:99 \
        --measurements-root "$REPO/measurements" \
        --note "Weekly regression run, unattended, systemd oneshot with no login session."; then
    # D-06 plus D-08: a run refused on a precondition produces the same recorded gap as a
    # missed week. It does not produce a retry.
    "$BIN" series --record-refusal "$(cat /run/nrmeasure-refusal 2>/dev/null || echo unknown)"
    git add metrics/coverage.json
    git -c user.name=neurorust-rig -c user.email=rig@localhost \
        commit -m "metrics: record coverage gap for refused weekly run"
    push_to_origin
    exit 0
fi

"$BIN" verify --write-index
"$BIN" verify --strict --check-index
"$BIN" series --append

# D-07: the weekly p50/p95/p99 JSON is a regression-tracking artifact and auto-commits.
# Anything that becomes a published claim reaches main only through a reviewed commit, so
# this script never touches docs/ and never edits metrics/baseline.json.
git add measurements metrics/latency-series.json metrics/coverage.json measurements/INDEX.md
git -c user.name=neurorust-rig -c user.email=rig@localhost \
    commit -m "metrics: weekly run $(date -u +%Y-%m-%d)"

push_to_origin
```

The credential helper reads the token from a root-owned file rather than embedding it in the unit
or the environment, so it does not reach `systemctl show` or the journal. Keeping it out of `ps`
depends entirely on the quoting: a double-quoted `credential.helper` is expanded by this shell
before `git` is executed, so the token becomes part of `git`'s argv and any user on the machine
can read it. Single quotes are what make the claim true, and `TOKEN_FILE` is exported so the
shell `git` spawns to run the helper can still resolve it. Both push sites go through
`push_to_origin` so the refusal path, which is the one that runs when nobody is watching, cannot
end up with weaker handling than the success path. State all of this in a comment in the script
itself, not only here.

Note that this wrapper needs no start delay. The `--start-delay` gap recorded in
`deferred-items.md` is about launching a capture from an open SSH session, where
`NoActiveSshSessions` observes the launching connection. The timer fires with nobody connected.
Say so in a comment so nobody adds a delay here by analogy.

`deploy/systemd/install.sh` copies the two units into `/etc/systemd/system/`, runs
`systemctl daemon-reload`, and enables and starts the timer. It must be idempotent and must refuse
to run if `/etc/neurorust/push-token` is absent or is not mode 0600 owned by root, because
installing a timer that will fail its push every week is worse than not installing it. It must

```yaml
name: regression

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read

concurrency:
  group: regression-${{ github.ref }}
  cancel-in-progress: true

jobs:
  regression:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      # The base revision belongs to the event.
      #
      # The earlier version of this workflow used `git merge-base origin/main HEAD` for both
      # events. On a push to main, origin/main and HEAD are the same commit, the merge base
      # is that commit, and the diff against it is empty: the guard below could not see any
      # change and let through exactly the simultaneous baseline move it exists to prohibit.
      # Finding 10 of 01-EXTERNAL-AUDIT.md.
      - name: Resolve the base revision
        id: base
        run: |
          if [ "${{ github.event_name }}" = "pull_request" ]; then
            base="${{ github.event.pull_request.base.sha }}"
          else
            base="${{ github.event.before }}"
            # A brand new branch reports an all-zero before-sha; fall back to the first
            # parent of HEAD, which is the previous tip on a fast-forward push.
            case "$base" in
              0000000000000000000000000000000000000000|"") base="$(git rev-parse HEAD^)" ;;
            esac
          fi
          git cat-file -e "$base^{commit}" || { echo "base revision $base is not in this clone"; exit 1; }
          echo "sha=$base" >> "$GITHUB_OUTPUT"
          echo "base revision: $base"

      # T-1-04: the baseline must not move in the same push as the run being compared
      # against it.
      - name: The baseline and the series did not change together
        run: |
          changed=$(git diff --name-only "${{ steps.base.outputs.sha }}" HEAD)
          if echo "$changed" | grep -qx 'metrics/baseline.json' \
             && echo "$changed" | grep -qx 'metrics/latency-series.json'; then
            echo "metrics/baseline.json and metrics/latency-series.json changed together."
            echo "Moving the baseline in the same push as the run it is compared against"
            echo "defeats the regression gate. Split them into two commits."
            exit 1
          fi

      # The baseline is changed only by a human, in a reviewed commit (D-07). The rig's
      # unattended wrapper never touches it, so a baseline change authored by the rig
      # identity is either a bug in the wrapper or something worse.
      - name: The baseline was not moved by the unattended job
        run: |
          for c in $(git rev-list "${{ steps.base.outputs.sha }}..HEAD"); do
            if git show --name-only --format='%an' "$c" | head -1 | grep -qx 'neurorust-rig' \
               && git show --name-only --format='' "$c" | grep -qx 'metrics/baseline.json'; then
              echo "commit $c is authored by neurorust-rig and changes metrics/baseline.json"
              exit 1
            fi
          done

      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2

      - name: Compare against the reviewed baseline
        run: |
          git show "${{ steps.base.outputs.sha }}:metrics/baseline.json" > /tmp/baseline-at-base.json
          cargo build -p nr-cli --release
          ./target/release/nrmeasure series --compare --baseline /tmp/baseline-at-base.json
```

Reading the baseline from the event's base revision rather than from the working tree is what
makes the gate resistant to being moved, and the author check is what makes the unattended path
unable to move it at all.

Two properties that must not be weakened:

  The workflow token is read-only. The rig pushes with its own credential; CI only judges. D-11
  says the rig measures and pushes and a GitHub Actions workflow compares, so a CI job with write
  access would blur that split.

  A regressed run is never withheld. D-11 is explicit that the harness never withholds a regressed
  run, because a bad run is evidence under BENCH-06. The gate fails the check; it does not revert
  the commit, does not delete the run, and does not filter it from the series. The failing check
  is the signal and the evidence stays published.

Also commit the initial `metrics/latency-series.json` and `metrics/coverage.json` produced by
`series --append`, so the files exist with real content and the weekly job appends rather than
creating.
