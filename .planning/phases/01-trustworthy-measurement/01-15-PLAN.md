<objective>
Install the weekly job on the rig and watch the whole loop close once, unattended.

Purpose: BENCH-08's success criterion is that a CI job commits a weekly metrics JSON carrying p50,
p95 and p99 for every stage instrumented so far. Everything needed for that was authored in plan
01-14. This plan is the part that cannot be done from the dev host: putting the repository and the
credential on the rig, enabling the timer, and confirming that a run reaches the repository and a
verdict reaches CI with nobody watching.

Until this plan completes, the weekly job is a set of files that have never run. A systemd unit
that has not fired is not a working job, and the failure modes here are unglamorous and real: a
credential with the wrong scope, a timer enabled but not started, a working tree the service user
cannot write to, a push that needs an interactive prompt.

**This plan needed targeted changes rather than a rewrite.** Its shape and its three tasks survive
the external audit and the D-26 and D-27 decisions intact. Five specific things changed and each
is called out where it applies:

  1. A run now carries fifteen precondition results, not fourteen. `NoActiveLoginSessions` was
     added after the first calibration runs.
  2. The weekly capture's firmware instrument is `rtla hwnoise`, not `hwlatdetect`, because
     `hwlatdetect` cannot sample the isolated cores on this kernel.
  3. The unattended `/opt/neurorust` checkout and the operator's `~/neurorust` checkout are two
     different trees, and `scripts/nr-run-measurement` pins the second one. Both must be
     confirmed to be running the same harness build, or the difference recorded.
  4. The unit is bounded by `TimeoutStartSec`, and the journal must not carry systemd's
     `RuntimeMaxSec= has no effect` line.
  5. The regression workflow now resolves an event-specific base revision and refuses a baseline
     change authored by the rig identity, so the weekly baseline seeding commit must be made by a
     human, on its own.

This plan runs on the Dell Precision 3591 and in the GitHub web interface. An executor agent
working from the macOS dev host cannot perform any task in it. Every task is a runbook.

Output: an installed, enabled, observed-working weekly job, and the first weekly run in the series
with its baseline seeded in a reviewed commit.

Two halves: the credential, then the deployment.

**Create the token.** In the GitHub web interface, under Settings, Developer settings, Personal
access tokens, Fine-grained tokens:

  - Resource owner: the account that owns this repository
  - Repository access: Only select repositories, and select this repository alone
  - Permissions: Contents, Read and write. Nothing else. Do not grant Actions, Workflows,
    Administration or Secrets
  - Expiration: 90 days

Do not use a classic personal access token. A classic token cannot be scoped to a single
repository, so a lost laptop would expose every repository the account can reach. That is threat
T-1-01 and the fine-grained token is the whole mitigation.

Write the expiry date into `deploy/systemd/README.md` under a heading "Credential rotation", with
the date the token must be replaced and a one-line procedure. A credential that silently expires
turns into eight weeks of coverage gaps before anyone notices, and D-08 means those gaps are
recorded rather than backfilled, so the series would show the outage without explaining it.

**Install the credential on the rig:**

```sh
sudo mkdir -p /etc/neurorust
printf '%s' '<the token>' | sudo tee /etc/neurorust/push-token > /dev/null
sudo chown root:root /etc/neurorust/push-token
sudo chmod 0600 /etc/neurorust/push-token
sudo chmod 0700 /etc/neurorust
sudo ls -l /etc/neurorust/push-token
history -d $((HISTCMD-4)) 2>/dev/null || true
```

Use `printf '%s'` rather than `echo` so no trailing newline is written; a trailing newline in the
token file breaks the credential helper with an unhelpful authentication error.

**Deploy the repository:**

```sh
sudo git clone https://github.com/<owner>/neurorust.git /opt/neurorust
sudo git config --global --add safe.directory /opt/neurorust
sudo chown -R root:root /opt/neurorust
sudo chmod -R go-w /opt/neurorust
cd /opt/neurorust
sudo cargo build -p nr-cli --release
sudo /opt/neurorust/target/release/nrmeasure --version
```

`/opt/neurorust` must be root-owned and not writable by anyone else. `install.sh` refuses
otherwise, for the same reason `deploy/sudoers/install.sh` checks `/usr/local/sbin`: a root unit
whose `ExecStart` lives in a user-writable tree is a root shell for anything running as that user.

**Confirm the two checkouts run the same harness build.** This is new, and it matters. The timer
runs `/opt/neurorust/target/release/nrmeasure`; the interactive entry point
`/usr/local/sbin/nr-run-measurement` pins `/home/<user>/neurorust/target/release/nrmeasure`. Two
trees, two builds, and every manifest since plan 01-16 records which one produced it:

```sh
sudo /opt/neurorust/target/release/nrmeasure --version
~/neurorust/target/release/nrmeasure --version
sha256sum /opt/neurorust/target/release/nrmeasure ~/neurorust/target/release/nrmeasure
git -C /opt/neurorust rev-parse HEAD
git -C ~/neurorust rev-parse HEAD
```

If the two commits differ, bring them into step before continuing, or record the difference in
`deploy/systemd/README.md` under a heading "Two checkouts" with the reason. Do not leave it
undocumented: a weekly figure and a headline figure produced by different builds, with nothing
saying so, is exactly the provenance gap plan 01-16 closed in the manifest and would reopen here
in the operating procedure.

The separate checkout is deliberate. The unattended job should not compete with an interactive
working tree, and a dirty interactive tree would otherwise be what the service builds and measures
from.

## Trust boundaries

| the rig -> the public repository | An unattended process on a personal laptop can write to a public repository every week |
| the GitHub UI -> the token scope | The scope chosen at creation time is the only thing bounding what a stolen token can do |
| the timer -> an unattended measurement | Nobody is watching when this runs, so every safety property has to hold without a human |
| two checkouts -> one published series | Weekly and headline figures produced by different builds, with nothing saying so, is a provenance gap in the operating procedure rather than in the code |

| Threat ID | Category | Component | Disposition | Mitigation plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Elevation of privilege | /etc/neurorust/push-token, the GitHub token | mitigate | Fine-grained token, resource owner set to the repository owner, repository access limited to this one repository, permissions limited to Contents read and write, with a 90 day expiry recorded in `deploy/systemd/README.md`.
