### Format

Line 1 is the literal `# Histogram`.
Data lines are `%06d` bin index followed by one `%06d` count per column. The first separator
is a space and the rest are tabs, so split on any whitespace.
Bin index is latency in microseconds at 1 us resolution.

This file has 6 columns for 6 threads, which means it came from `-h 400` (plain histogram).

<threat_model>
## Trust boundaries

| Boundary | Description |
|----------|-------------|
| crates.io -> the build | Third-party crate source is compiled and later runs as root on the rig |
| GitHub Actions runner -> the repository | The workflow token can write if not constrained |

## STRIDE threat register

| Threat ID | Category | Component | Disposition | Mitigation plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-08 | Tampering | workspace dependency tree | mitigate | `deny.toml` plus the `deny` CI job run `check advisories licenses bans sources`; `Cargo.lock` is committed so the audited set is the built set; `unknown-git = "deny"` blocks git dependencies entirely |
| T-1-11 | Elevation of privilege | .github/workflows/ci.yml | mitigate | `permissions: contents: read` at workflow level; no secrets referenced in ci.yml; the only workflow that needs write access is the regression gate in plan 01-14 and it scopes its own token |
| T-1-12 | Tampering | third-party GitHub Actions | accept | Actions are pinned by major version tag (`@v4`, `@v2`) rather than by commit SHA. Rationale: this is a public repo with no deployment secrets in ci.yml, and the blast radius of a compromised action is a failed build, not a leaked credential. Revisit if a workflow ever gains write scope beyond plan 01-14's single-repo token. |
| T-1-13 | Tampering | `unsafe_code = "forbid"` in workspace lints | mitigate | The harness has no reason to use `unsafe`; forbidding it workspace-wide removes a whole class of memory-safety review from a tool that will run as root on the rig |
</threat_model>
