<objective>
Build the capture crate: the D-06 preconditions, the D-14 environment snapshot readers, and the
D-15 automatic contamination verdict.

Purpose: PLAT-02 needs a measurement protocol a third party can follow, and D-06 makes the
harness's own assertion list double as that checklist. The harness asserts and refuses; it never
mutates system state, because an enforcing harness would need root privileges it should not have
and would hide the very state a reader needs to reproduce. D-15 mechanises the lesson the
2026-08-28 baseline taught: that run was only diagnosable because someone thought to check CAL
counts after the fact, and this crate makes that check automatic.

RESEARCH.md pitfall 5 applies with full force here. procfs and sysfs are Linux only, so the
naive implementation makes every meaningful test Linux-gated and the macOS CI leg decorative.
The design below reads all system facts through one trait so every check has a real test on both
platforms, driven by the fixtures plan 01-02 brought back from the rig.

Output: `nr-capture` with 14 typed checks, an environment snapshot that fills the D-14 manifest
fields, and a contamination verdict with a calibration-aware third state.
</objective>

```rust
/// Everything the precondition checks and the environment snapshot need to read.
/// One live implementation (Linux, procfs and sysfs) and one fixture implementation
/// (parses the text files plan 01-02 captured on the rig). The fixture implementation is
/// what makes the macOS CI leg test real logic rather than nothing.
pub trait SystemFacts {
    fn read_text(&self, path: &str) -> Result<String, FactsError>;
    fn path_exists(&self, path: &str) -> bool;
    fn systemctl_show(&self, unit: &str, props: &[&str]) -> Result<BTreeMap<String, String>, FactsError>;
    fn systemctl_get_default(&self) -> Result<String, FactsError>;
    fn active_ssh_sessions(&self) -> Result<u32, FactsError>;
    fn graphical_sessions(&self) -> Result<u32, FactsError>;
    fn running_processes_matching(&self, names: &[&str]) -> Result<Vec<String>, FactsError>;
}

#[cfg(target_os = "linux")]
pub fn live() -> Result<LiveFacts, FactsError>;

pub struct FixtureFacts { /* built from a probe-sysfs-tuning.txt style key=value file
                             plus an optional map of extra path -> contents */ }
```

`run_all(&facts, &spec) -> Vec<PreconditionResult>` must return exactly 14 results in a stable
order every time, including for checks that could not be evaluated. A check that cannot read its
source returns `Unavailable` with `observed` naming the missing path. Never omit a result: the
manifest records what was seen, and a silently missing check is indistinguishable from a check
that passed.

`refuse_on_violation(&[PreconditionResult]) -> Result<(), RefusalError>` returns `Err` when any
result is `Fail`, or when any result is `Unavailable` and the run's instrument class is
`HeadlineSeries`. `RefusalError` lists every offending check with its observed and expected
values, because an operator who has to make three trips to the rig to find three violations will
stop using the harness.

The crate must contain no write to `/sys`, `/proc` or `/etc`, and must not invoke `sysctl`,
`cpupower`, `tuned` or any state-changing command. D-06 is explicit: the harness changes nothing.

Parse `/proc/interrupts` with `procfs` 0.18.0 on Linux and with a small fixture parser for tests.
RESEARCH.md lists hand-rolling this under "Don't hand-roll" because of per-CPU columns, variable
IRQ naming and architecture-specific rows, so use `procfs::interrupts()` for the live path. The
fixture path parses the same text format for tests; keep the fixture parser to the columns and
rows actually needed rather than reimplementing procfs.

```rust
pub struct InterferenceSnapshot {
    pub utc: OffsetDateTime,
    pub per_cpu: BTreeMap<u32, CounterSet>,   // only the isolated CPUs
    pub context_switches: u64,                // /proc/stat ctxt
}

pub struct CounterSet {
    pub cal: u64,          // function call IPIs, the 2026-08-28 diagnostic signal
    pub tlb: u64,          // TLB shootdowns
    pub res: u64,          // rescheduling interrupts
    pub loc: u64,          // local timer interrupts
    pub nmi: u64,
    pub device_irqs: u64,  // sum of all numbered IRQ rows on this CPU
}
```

Counters to diff, and why each one: CAL and TLB are the pair the 2026-08-28 post-mortem found
diagnostic (an SSH session's process creation broadcast TLB shootdown IPIs to the isolated
cores). RES indicates the scheduler trying to move work onto an isolated core. LOC on an
`isolcpus`-only core still ticks, so its rate is the direct evidence for RESEARCH.md open
question 4. NMI and device IRQs cover the rest.

`config/contamination-thresholds.json` is the committed configuration. Ship it in the
uncalibrated state, because D-17 fixes that the thresholds are derived from a deliberate
calibration pair that has not been run yet. The file shape:

```json
{
  "schema_version": 1,
  "status": "uncalibrated",
  "calibration": {
    "derived_from": [],
    "note": "Thresholds are derived from the D-17 calibration pair in plan 01-11: one run under the clean protocol and one deliberately reproducing the 2026-08-28 conditions. Until that pair exists the verdict is uncalibrated, which is reported as such and never rendered as a pass."
  },
  "per_run_hour": {
    "cal_delta_max": null,
    "tlb_delta_max": null,
    "res_delta_max": null,
    "device_irq_delta_max": null,
    "context_switch_delta_max": null
```

## Trust boundaries

| Boundary | Description |
|----------|-------------|
| system state -> a published figure | If a precondition is not asserted, a contaminated run enters the series and every number downstream inherits it |
| /proc and /sys -> the harness | Kernel-provided text is parsed; a format change on a kernel upgrade is a silent failure risk |
| the harness -> the rig | The harness runs with elevated privilege during a measurement and must not change the machine it is measuring |

| T-1-02 | Tampering | preconditions.rs | mitigate | All 14 checks run and all 14 results are recorded, pass or fail. `refuse_on_violation` stops the run on any Fail, and on any Unavailable for a headline-class run, so a check that could not be evaluated is never silently treated as a pass. `nr-manifest` rejects a harness-generated manifest whose `preconditions` array is empty. |
