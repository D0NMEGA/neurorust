**Step 2, the build script.** Extend `crates/cli/build.rs` with a middle branch. The order is git
first, then the stamp, then unavailable, because a real repository read is always better evidence
than an assertion:

```rust
fn main() {
    let sha = git(&["rev-parse", "HEAD"]);
    let dirty = git(&["status", "--porcelain"]).map(|s| !s.trim().is_empty());
    match (&sha, dirty) {
        (Some(sha), Some(dirty)) => { /* unchanged: build-time */ }
        _ => match read_stamp() {
            Some(stamp) => {
                println!("cargo:rustc-env=NR_BUILD_GIT_SHA={}", stamp.sha);
                println!("cargo:rustc-env=NR_BUILD_GIT_DIRTY={}", stamp.dirty);
                println!("cargo:rustc-env=NR_BUILD_GIT_SHA_SOURCE=pushed-stamp");
            }
            None => { /* unchanged: unavailable */ }
        },
    }
    println!("cargo:rerun-if-changed=../../.git/HEAD");
    println!("cargo:rerun-if-changed=../../.git/index");
    println!("cargo:rerun-if-changed=../../.git-sha");
}
```

`read_stamp` parses `../../.git-sha`, one `key=value` per line, and returns `None` unless it finds
a `sha` of exactly 40 lowercase hex characters and a `dirty` of exactly `true` or `false`. A
malformed stamp yields `None` and the build falls through to `unavailable`: a half-read stamp must
never become a confident sha. Mirror `git`'s existing contract, never panic and never fail the
build.

**Step 3, the push script.** Write `scripts/nr-push-to-rig.sh`, POSIX shell, `set -eu`, ASCII only,
executable, run from the dev host (macOS), with the repository root as its working directory:

```sh
#!/bin/sh
# nr-push-to-rig.sh [--allow-dirty] [host]
#
# The one supported way this repository's source reaches the reference rig.
#
# The rig has no git and ~/neurorust there is an rsync mirror with no .git, so
# crates/cli/build.rs cannot read a revision when it compiles there. This script stamps the
# revision it is pushing into .git-sha, which build.rs reads and records as
# git_sha_source: pushed-stamp: an asserted revision, labelled as asserted.
#
# It never sends measurements/, metrics/, target/, .git/, .planning/ or CLAUDE.md. The rig holds
# captures the dev host has not seen yet, and rsync must not be able to touch them.
set -eu

HOST=precision3591-rig
ALLOW_DIRTY=0
...
```

Requirements on the script, each of which has a reason:

  - Refuse when `git rev-parse HEAD` fails. Without a revision there is nothing to stamp and the
    push would silently leave a stale `.git-sha` behind.
  - Refuse when `git status --porcelain` is non-empty, unless `--allow-dirty` was given, in which
    case stamp `dirty=true`. An unannounced dirty push is how a sha stops describing the bytes.
  - Write `.git-sha` with exactly three lines: `sha=<40 hex>`, `dirty=true|false`,
    `stamped_utc=<RFC 3339>`.
  - Push an explicit list of source paths rather than the whole tree with exclusions:
    `Cargo.toml Cargo.lock crates schemas config scripts deploy docs .git-sha`. An include list
    fails closed; an exclude list fails open, and the thing it would fail open onto is
    `measurements/`.
  - Send `.git-sha` last, in its own `rsync` invocation, so a transfer that dies partway leaves
    the stamp describing the previous, complete push rather than a partial one.
  - Verify the stamp arrived byte-identical, comparing `shasum -a 256 .git-sha` on the dev host
    against `sha256sum ~/neurorust/.git-sha` on the rig, and refuse if they differ. This is the
    same after-transfer verification plan 01-22 used when it pushed the six root scripts by hand.
  - Print the sha, the dirty flag and every path sent, so the operator's terminal is a record of
    what the rig now holds.
  - Never run `sudo` and never install anything. Installing the root scripts stays a separate,
    deliberate step (`deploy/sudoers/install.sh`), because that is what the D-26 sudoers grant is
    scoped around.
