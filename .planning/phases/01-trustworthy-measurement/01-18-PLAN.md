<objective>
Close audit finding 8 and the remaining half of finding 5: make each gate establish the exact
proposition its name claims, and decide the thermal exemption from a declared profile rather
than from the temperature that happened to be observed.

Purpose: the D-06 assertion list is what PLAT-02 turns from a document into a mechanism, and it
doubles as the third-party reproduction checklist. A check whose name overstates what it read is
worse than no check, because a reader takes the name at face value.

Three are overstated today.

`crates/capture/src/preconditions.rs:384` reads `/sys/devices/system/cpu/cpu0/cpuidle/...` and
reports `DeepCstatesDisabled`. The rig tunes C-states per CPU through sysfs, and the run isolates
CPUs 6 to 11. CPU 0's cpuidle tree says nothing about them.

`preconditions.rs:594` treats `current_tracer == nop` as tracer quiescence. The `current_tracer`
selector is one of several independent tracing controls; `events/enable`, `set_event` and
`tracing_on` each arm tracing without changing it. A headline run can therefore pass
`TracersQuiescent` with event tracing running.

`crates/cli/src/cmd/run.rs:232` forbids the facts fixture for publishable run classes but leaves
the interrupts fixture accepted at line 315, and that one fixture text is read for the before and
the after snapshot, so every counter delta computed from it is exactly zero. A zero delta reads
as a perfectly quiet machine.

And finding 5: the `Screen` thermal exemption at `preconditions.rs:552` applies to every
`Screen`-class run, and it applies only after the observed temperature has already exceeded the
ceiling. An unintentionally hot idle screen therefore gets the same exemption as a deliberately
saturated firmware screen. The exemption is right; keying it on the outcome is not.

Do not weaken anything here. Plan 01-05 recorded that `GovernorIsPerformanceOnAllCpus` and
`TracersQuiescent` correctly FAIL against the rig's ordinary desktop state, and that is the
assertion list working. This plan makes two checks stricter and one exemption narrower.

Runs entirely on the macOS dev host, against the committed fixtures. No rig access.

Output: three widened gates, a declared thermal profile, a manifest that names any fixture it
was driven by, and a test that keeps the protocol document and the code stating the same ceiling.
</objective>

## Trust boundaries

| Boundary | Description |
|----------|-------------|
| a check's name -> the proposition it establishes | The assertion list is also the third-party reproduction checklist, so an overstated name misleads a reader who cannot read the code |
| a test fixture -> a published figure | A fixture seam that reaches a publishable class turns synthetic input into published evidence |
| an observed temperature -> an exemption | An exemption decided from the observation it is meant to constrain cannot constrain anything |
