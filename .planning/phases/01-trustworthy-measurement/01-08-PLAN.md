CI.

Purpose: D-13 says CI enforcement is blocking, and that any capture or figure under
`measurements/` must have a manifest with all required fields present and checksums matching or

Argument surface:

```
nrmeasure verify
  --root <path>            default . (the repository root)
  --measurements <path>    default ./measurements
  --strict                 treat warnings as failures; the CI gate passes this
  --write-index            regenerate measurements/INDEX.md from the manifests
  --check-index            fail if measurements/INDEX.md differs from the generated form
```

Three checks, run over the whole tree, all failures collected before exiting:

  Check 1, every run directory is complete. For each immediate subdirectory of `measurements/`:
  require a readable `manifest.json`, deserialise it into `RunManifest` (which enforces the
  required fields), and call `nr_manifest::validate`, which re-checks every artifact checksum and
  the path safety rules. Report every `ValidationError` with the run directory that produced it.

  Check 2, no stray captures. Walk the whole repository, excluding `.git`, `target` and anything
  matched by `.gitignore`. A file is capture-shaped when it matches any of:

```
  *.hist
  cyclictest*.json
  hwlatdetect*.txt
  *.trace.dat
  trace-*.txt
  timerlat*.txt
  osnoise*.txt
```

  A capture-shaped file is acceptable only in one of three places:
    a. inside a run directory under `measurements/` that has a valid manifest listing it
       (matched by path and by blake3, so a file present on disk but absent from the manifest
       fails)
    b. under `crates/*/tests/fixtures/`
    c. under `docs/rig/recon-*/` with a filename beginning `probe-`
  Anything else fails with the path named. This is the T-1-05 mitigation: the gate is scoped by
  what a file *is*, not only by where it sits, so moving a figure out of `measurements/` does not
  evade it. The two exempt trees are narrow, named in the code as constants, and documented in
  `docs/publication-layout.md` (plan 01-09).

  Check 3, the index. With `--write-index`, regenerate `measurements/INDEX.md` from every
  manifest via `nr_metrics::index::render_index` and write it. With `--check-index`, generate and
  compare, failing on any difference. The CI gate uses `--check-index` so a hand-edited index,
  which is the easy way to make a losing configuration disappear from the published surface,
  fails the build.

Exit codes: 0 on success, 1 on any check failure. Print a summary line first
(`verify: N run directories, M problems`), then one line per problem, each beginning with the
path so the output greps cleanly.

Do not add a directory-walking dependency. `std::fs::read_dir` recursion is sufficient and keeps
the dependency set as small as the supply-chain gate assumes. Honour `.gitignore` by shelling out
to `git ls-files --cached --others --exclude-standard` when a git repository is present, and
falling back to a plain walk with a hardcoded skip list (`.git`, `target`) when it is not. Using
the git index is both simpler and more correct: the gate should judge what is committed.

```
nrmeasure reconstruct <run-dir>

  --note <text>                optional
  --force                      overwrite an existing manifest.json
```

The command reads what is there and marks what is not. Three rules, each enforced:

  1. `provenance_tier` is hardcoded to `ProvenanceTier::Reconstructed`. There is no flag to
     change it. RESEARCH.md pitfall 6 names the trap directly: defaulting or allowing the tier to
     be set makes a reconstructed manifest indistinguishable from a real one.

  2. Every manifest field that cannot be traced to a value in `RIG.txt`, the README, or the run
     directory's own files is left `None` and recorded in `absent_fields` with a reason naming
     the source that did not carry it, for example
     `{ "field_path": "preconditions", "reason": "the harness did not exist when this capture was taken" }`
     and
     `{ "field_path": "tuning.per_cpu_governor", "reason": "RIG.txt records a single governor value, not a per-CPU list" }`.
     Never copy a value from a different run and never substitute a plausible default. This is
     D-16's central rule and `nr_manifest`'s `ReconstructedWithoutAbsentFields` check is the
     backstop.

  3. `--verdict` is required with no default. A contamination verdict is computed from before and
     after interference snapshots, which a pre-harness capture does not have. Requiring the
     operator to state it, and requiring an exclusion reason when it is `contaminated`, keeps the
     judgement visible rather than implied.

Two properties of this workflow are load-bearing and must not be changed casually:

  It runs on pull_request as well as push, so a figure cannot reach main without passing. D-13
  says the commit cannot merge, which requires the check to run on the pull request and to be
  marked as required in the branch protection settings. Note in the plan summary that marking it
  required is a repository setting a human applies once in the GitHub UI; the workflow alone does
  not enforce it.

  the index would let a hand-edited index be silently repaired, which defeats the purpose: the

<threat_model>
## Trust boundaries

| Boundary | Description |
|----------|-------------|
| a pull request -> main | The gate is the only mechanical barrier between an unstamped figure and the published repository |
| manifest.json on disk -> verify | A manifest is untrusted input and may have been hand-written to pass |
| measurements/INDEX.md -> a reader | The index is the published surface where losing configurations appear |

## STRIDE threat register

| Threat ID | Category | Component | Disposition | Mitigation plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-05 | Tampering | verify.rs check 2 | mitigate | The stray-capture scan is scoped by file shape across the whole git-tracked tree, not by directory. Seven capture-shaped patterns are matched, and only two narrow exempt trees are allowed: `crates/*/tests/fixtures/` and `docs/rig/recon-*/` with a `probe-` prefix. Committing a figure at the repository root fails the gate. |
| T-1-03 | Tampering | verify.rs check 1 | mitigate | Every artifact checksum is recomputed and compared, and a file present on disk but absent from the manifest fails. `nr_manifest::validate` supplies the required-field and path-safety checks; verify adds the tree-level ones. |
| T-1-27 | Tampering | verify.rs check 3, INDEX.md | mitigate | The CI gate uses `--check-index`, never `--write-index`, so a hand-edited index fails the build rather than being silently regenerated. Deleting a losing configuration's row is therefore a build failure, which is what BENCH-06 requires to be more than an intention. |
| T-1-28 | Spoofing | reconstruct.rs | mitigate | The provenance tier is hardcoded to `Reconstructed` with no flag to override it, and `nr_manifest` rejects a reconstructed manifest that records no absent fields. A reconstructed manifest therefore cannot present itself as harness-generated. |
| T-1-11 | Elevation of privilege | provenance.yml | mitigate | `permissions: contents: read` and no secrets. The gate reads and reports; it never writes to the repository, so a compromised step cannot commit a passing state. |
</threat_model>
