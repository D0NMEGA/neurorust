<objective>
Put the rig's root entry point on a stated, version-controlled footing, and probe the two new
instruments' real output formats before anything is written to parse them.

Purpose: three things converge on one interactive sudo session at the rig.

D-26: a narrowly scoped passwordless sudoers entry authorizes launching a measurement. Today the
rig grants NOPASSWD to three argument-free scripts (`nr-recon`, `nr-probe`, `nr-measure-mode`)
and, since 2026-09-04, to `nr-run-measurement`. That fourth grant was added by hand during plan
01-11 and exists nowhere in this repository: not the rule, not the install procedure, not a
record of the file's ownership or mode. A passwordless root grant that lives only on one laptop
is exactly the configuration nobody can review.

The `TimeoutStartSec` fix. `scripts/nr-run-measurement` in this repository already passes
`--property=TimeoutStartSec="$RUNTIME_MAX"`, but the copy installed at
`/usr/local/sbin/nr-run-measurement` is the earlier version that passed `RuntimeMaxSec`, which
systemd ignores on a `Type=oneshot` unit and says so in the journal every run:
`nr-measurement.service: RuntimeMaxSec= has no effect in combination with Type=oneshot.
Ignoring.` Until the installed copy is replaced, a hung capture still needs the operator's
password to clear, which is the situation commit 178c7e8 was written to end.

D-27's instruments. `rtla hwnoise` and `rdmsr -p <cpu> 0x34` are about to become the firmware
screen, and neither has ever been run on this rig. Plan 01-04 recorded the lesson that a parser
written against an assumed column layout is wrong and a parser written against a real capture is
right. This plan takes the capture.

This plan runs on the Dell Precision 3591 and needs the operator's own interactive sudo. An
executor agent working from the macOS dev host cannot perform tasks 1 or 2. Task 3 runs on the
dev host from what tasks 1 and 2 bring back.

Output: a version-controlled sudoers rule and four version-controlled root scripts, a rig whose
installed copies match them, `msr-tools` and `stress-ng` installed, and two committed format
probes.

**Step 2, add the three tracing writes to `scripts/nr-measure-mode`.** Plan 01-18 widened
`TracersQuiescent` to require four controls, and this script currently writes only the first:

```sh
echo nop | tee /sys/kernel/tracing/current_tracer > /dev/null
echo 0   | tee /sys/kernel/tracing/events/enable  > /dev/null
echo     | tee /sys/kernel/tracing/set_event      > /dev/null
echo 0   | tee /sys/kernel/tracing/tracing_on     > /dev/null
```

Add the three, in `nr-measure-mode on`, next to the existing tracer write. Its `off` path and its
`status` path get the matching reads so an operator can see all four. Do not weaken the
precondition to match the old script; the script follows the check.

**Step 3, harden `scripts/nr-run-measurement`.** Two additions, both concrete:

  a. Set a fixed PATH as the first executable line and use absolute paths for the two commands
     the script runs as root:

     ```sh
     PATH=/usr/sbin:/usr/bin:/sbin:/bin
     export PATH
     ```
     and call `/usr/bin/systemd-run` and `/usr/bin/systemctl` by absolute path. `sudo`'s
     `secure_path` normally supplies this, but a script that runs as root under NOPASSWD should
     not depend on a setting in a file it does not control.

  b. Refuse to exec a binary that anyone but root can write, and record which binary it ran:

     Read `stat -c '%a'` and refuse when the group or other write bit is set, printing the
     observed mode and the path. Then print the binary's checksum before launching, so the
     journal records which build ran:

     ```sh
     echo "nr-run-measurement: exec $BIN"
     echo "  sha256: $(sha256sum "$BIN" | cut -d' ' -f1)"
     echo "  mode:   $(stat -c '%a %U:%G' "$BIN")"
     ```

     This does not stop the operator from replacing their own build output, and it is not meant
     to. It stops a group- or world-writable build directory from turning a passwordless grant
     into a root shell for any process on the machine, and it makes a substitution visible after
     the fact in the journal.

**Step 4, write the sudoers rule into the repository.** `deploy/sudoers/nr-measurement`, ASCII,
with a comment block naming what each grant is for:

```
# neurorust rig measurement grants.
#
# Each entry is a fixed absolute path to a root-owned, root-writable-only script.
# No entry grants a bare command with operator-supplied arguments: nr-recon, nr-probe
# and nr-measure-mode take no arguments at all, and nr-run-measurement pins every path
# it writes to (--measurements-root and --thresholds) and refuses to pass an override.
#
# Install with deploy/sudoers/install.sh, which validates with visudo -c before
# activating the file. Never edit /etc/sudoers.d/nr-measurement by hand.

d0nmega ALL=(root) NOPASSWD: /usr/local/sbin/nr-recon
d0nmega ALL=(root) NOPASSWD: /usr/local/sbin/nr-probe
d0nmega ALL=(root) NOPASSWD: /usr/local/sbin/nr-measure-mode
d0nmega ALL=(root) NOPASSWD: /usr/local/sbin/nr-run-measurement
```

and `deploy/sudoers/install.sh`, POSIX shell, `set -eu`, idempotent. It must:

  1. Install each script from `scripts/` to `/usr/local/sbin/` with
     `install -o root -g root -m 0755`. Root-owned and not writable by the operator: a
     NOPASSWD-executable script the invoking user can edit is a root shell, and that is the
     single most important property of this whole arrangement.
  2. Install the rule to a temporary file, run `visudo -c -f <tmp>`, and only then
     `install -o root -g root -m 0440` it to `/etc/sudoers.d/nr-measurement`. A syntactically
     broken sudoers file can lock the machine out of sudo entirely, so it is validated before it
     is activated, never after.
  3. Refuse and exit non-zero if any script in `scripts/` is missing, or if `/usr/local/sbin` is
     writable by anyone but root.
  4. Print `sudo -l` at the end so the operator sees the resulting grant.

If a `/etc/sudoers.d/nr-run-measurement` file already exists from the 2026-09-04 hand
installation, remove it in the same session, so exactly one file describes the grant.

**Probe rdmsr.** Read `MSR_SMI_COUNT` on every CPU the runtime isolates plus two housekeeping
CPUs, so the parser knows what a per-CPU read looks like and what an error looks like:

```sh
{
  echo "# rdmsr -p <cpu> 0x34   (MSR_SMI_COUNT), taken $(date -u +%FT%TZ)"
  echo "# msr-tools version: $(dpkg-query -W -f='${Version}' msr-tools)"
  echo "# kernel: $(uname -r)"
  for cpu in 0 5 6 7 8 9 10 11; do
      printf 'cpu %-2s 0x34 = ' "$cpu"
      sudo rdmsr -p "$cpu" 0x34 2>&1 || true
      echo
  done
  echo "# decimal form, -d:"
  for cpu in 6 11; do
      printf 'cpu %-2s 0x34 = ' "$cpu"
      sudo rdmsr -d -p "$cpu" 0x34 2>&1 || true
      echo
  done
} | tee /tmp/probe-rdmsr-smi-count.txt
```

thing three fifteen-minute `hwlatdetect` arms could not establish.

<threat_model>
## Trust boundaries

| Boundary | Description |
|----------|-------------|
| the operator account -> root, without a password | A NOPASSWD sudoers entry converts anything the entry can reach into unprivileged-to-root escalation |
| operator-supplied arguments -> a root process | `nr-run-measurement` is the only grant that accepts arguments at all |
| userspace -> model-specific registers | `rdmsr` reads CPU registers directly through a kernel module whose device nodes exist for that purpose |
| a probe file -> the published repository | A raw tool capture committed outside `measurements/` bypasses the manifest contract by design and must not carry host identifiers |

## STRIDE threat register

| Threat ID | Category | Component | Disposition | Mitigation plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-70 | Elevation of privilege | /etc/sudoers.d/nr-measurement | mitigate | Each entry names one fixed absolute path. Three of the four scripts take no arguments at all. `install.sh` installs every script `-o root -g root -m 0755`, so the invoking user cannot edit a script the rule lets them run as root, which is the single failure that would turn this grant into a general root shell. The rule file itself is `0440 root:root` and is validated with `visudo -c -f` on a temporary copy before it is activated, because a malformed sudoers file locks the machine out of sudo entirely. |
| T-1-71 | Elevation of privilege | nr-run-measurement argument handling | mitigate | The script requires `run` as the first argument, rejects `--measurements-root` and `--thresholds` in any form, pins both, and `exec`s the binary with `"$@"` and no shell, so no argument is ever word-split or expanded by a shell. `--rig-slug` reaches a directory name but is bounded by `nr_manifest`'s run-id charset rule (lowercase ASCII, digits and hyphen, 64 characters), so traversal is rejected before a directory is created. `--note` is free text that reaches a published manifest and is redacted for home-directory prefixes by plan 01-16. |
| T-1-72 | Elevation of privilege | the pinned `$BIN` path | mitigate | `$BIN` is `/home/d0nmega/neurorust/target/release/nrmeasure`, a path the unprivileged operator owns, executed as root. | T-1-73 | Tampering | PATH and the environment of a root script | mitigate | `nr-run-measurement` sets `PATH=/usr/sbin:/usr/bin:/sbin:/bin` explicitly and invokes `systemd-run` and `systemctl` by absolute path, rather than relying on `sudo`'s `secure_path`, which lives in a file this repository does not control. |
