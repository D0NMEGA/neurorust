<objective>
Build `nrmeasure run`: the command that executes a measurement on the rig, stamps it with the
full D-14 environment snapshot, and writes a run directory that the provenance gate will accept.

Purpose: BENCH-04 says every published figure is stamped by the capture harness with rig, kernel,
BIOS revision and tuning state. This is the command that does the stamping. D-01 fixes that the
harness shells out to `cyclictest` and `hwlatdetect` but owns manifest generation, histogram
parsing, percentile computation and JSON emission. D-12 fixes that raw captures stay
byte-identical to what the tool emitted and that the human-readable summary is generated from the
manifest rather than hand-maintained.

The design constraint that shapes this plan: the executor works on macOS and cannot run
cyclictest. The integration test therefore drives the whole pipeline with fake tool binaries that
emit the committed fixture content, so the orchestration, the manifest emission and the report
rendering are all covered without a rig. Only the live `SystemFacts` source is Linux-gated.

Output: `nrmeasure run` producing a complete, valid, self-describing run directory.
</objective>


Order of operations, which is the whole point of the command:

  1. Resolve the tool paths and record their versions. Fail early if a tool is missing.
  2. Build the `SystemFacts` source. Run all 14 preconditions. Call `refuse_on_violation`.
     On refusal: print every offending check with its observed and expected value, exit with
     code 2, and write nothing. D-06 says the harness refuses; it does not proceed and annotate.
  3. Take the before interference snapshot.
  4. Execute `cyclictest` with the exact flag set below, writing its output files into a
     temporary directory owned by the command.
  5. If `--with-hwlatdetect`, execute `hwlatdetect` next, never concurrently. Two measurement
     tools running at once measure each other.
  6. Take the after interference snapshot and compute the verdict against the loaded thresholds.
  7. Take the environment snapshot.
  8. Parse the `.hist` (and the `--json` if produced) and reconcile them.
  9. Create the run directory, move the raw captures in unmodified, write `hist.tsv`.
 10. Compute blake3 over every artifact, assemble the manifest, validate it, write
     `manifest.json`.
 11. Render and write `REPORT.md`.
 12. Print the run directory path and the headline numbers to stdout.

The cyclictest invocation, built from the arguments above:

```
cyclictest --mainaffinity=<main-cpus> --affinity=<cpus> --threads=<count of cpus> \
           --mlockall --policy=fifo --priority=<priority> \
           --interval=<interval> --distance=0 \
           --histogram=<histogram-max> --histfile=<tmp>/cyclictest.hist \
           --json=<tmp>/cyclictest.json \
           --duration=<duration> \
           [--breaktrace=<us> --tracemark]
```

`--distance=0` keeps every thread on the same interval, which is what makes the per-thread
histograms comparable. Pass `--histogram-max` through to `parse_hist_file` as the declared
overflow bound so the parsed run records `OverflowBoundSource::Declared` rather than deriving it.

`tools.rs` owns process execution: resolve an absolute path for each tool once, capture the
version string, run with the argument vector built as a `Vec<String>` (never by string
concatenation and never through a shell), and record `name`, `version`, `argv` and `exit_code`
into the manifest. Allow the tool paths to be overridden by `NRMEASURE_CYCLICTEST` and
`NRMEASURE_HWLATDETECT` environment variables; the integration test in task 3 uses this to point
at the fake binaries.

Failure handling, which matters because BENCH-06 says failure cases are reported rather than
omitted: a tool that exits non-zero does not abort the write. Record the exit code, set
`excluded_from_series = true` with `exclusion_reason` naming the tool and the code, and write the
run directory anyway. The distinction is deliberate: a precondition violation means the
measurement was never valid to take, so nothing is written; a tool failure means a measurement
was attempted and its outcome is evidence.

`--dry-run` runs steps 1 and 2 and then prints the exact command lines that would be executed.
This is what a third party uses to check their environment against the protocol without taking a
measurement, so it belongs in `docs/measurement-protocol.md` (plan 01-09) as the first step.

<threat_model>
## Trust boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments -> the filesystem | The rig slug and run class become a directory name under measurements/ |
| the harness -> external tool processes | cyclictest and hwlatdetect run with elevated privilege and their argument vectors are constructed by the harness |
| a fixture-backed run -> a published figure | A test seam that produced a publishable run directory would be the worst possible defect in this project |

## STRIDE threat register

| Threat ID | Category | Component | Disposition | Mitigation plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-16 | Tampering | rundir.rs | mitigate | ASVS V12. The run id is validated against `^[a-z0-9][a-z0-9-]{0,63}$` before any directory is created, and the directory name is composed from a validated date, slug and class rather than from free text. `RunDir::create` refuses to write into a directory that already contains a manifest. |
| T-1-09 | Elevation of privilege | tools.rs | mitigate | Tool invocation uses `Command::new(absolute_path)` with an explicit `Vec<String>` argument vector and never a shell. There is no string interpolation into a command line, so a hostile rig slug or note cannot become an argument injection. Tool paths are resolved once and recorded in the manifest. |
| T-1-25 | Spoofing | cmd/run.rs NRMEASURE_FACTS_FIXTURE | mitigate | The fixture-backed facts source is refused for the `headline`, `weekly` and `soak` run classes, and a test asserts the refusal. A number that was never measured can therefore not enter the published series through the test seam. |
| T-1-02 | Tampering | cmd/run.rs step 2 | mitigate | The run refuses on a precondition violation before any tool executes and before any directory is created, so there is no partial run directory to be mistaken for a valid one. |
| T-1-26 | Information disclosure | cmd/run.rs manifest assembly | mitigate | `tools[].argv` records output paths, which live under a home directory on the rig. The redaction decision taken in plan 01-03 task 3 is applied here: whatever was decided for `argv` (verbatim, or paths relativised to the run directory) is what this command writes. |
</threat_model>
