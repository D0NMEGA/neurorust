Concrete validation rules:

  1. `run_id` must match `^[a-z0-9][a-z0-9-]{0,63}$`. Implement the check by hand with
     `chars().all(...)`; do not add a regex dependency. This is ASVS V12: the run id becomes a
     directory name, so a traversal in it becomes a write outside `measurements/`.
  2. Every `ArtifactRecord.path` must be relative, must not start with `/`, must contain no
     `..` component, and must not be absolute after normalisation.
  3. Every artifact whose `stored` is `InRepo` must exist under `run_dir` and its blake3 must
     match. An `External` artifact is checked for a non-empty URL only.
  4. `artifacts` must be non-empty.
  5. When `provenance_tier` is `HarnessGenerated`, `preconditions` must be non-empty. A
     reconstructed manifest may legitimately have none, because the checks were never run; in
     that case it must record that as an `AbsentField` with `field_path: "preconditions"`,
     which is what `ReconstructedWithoutAbsentFields` enforces: a `Reconstructed` manifest with
     an empty `preconditions` array and an empty `absent_fields` array is invalid. This is D-16
     made mechanical: never guessed, always explicitly absent.
  6. `excluded_from_series == true` requires `exclusion_reason` to be `Some` and non-empty.
     This is how BENCH-06 stops being an intention: a run kept out of the headline series has to
     say why, in the manifest, or it fails validation.
  7. `schema_version` must equal the crate's `SCHEMA_VERSION` constant (1).

Generate `schemas/manifest.schema.json` by running the crate's own generator, not by hand.
Add a binary target or a test-driven regeneration path. The simplest form that keeps CI honest:

```rust
// crates/manifest/tests/schema_up_to_date.rs
#[test]
fn schema_up_to_date() {
    let generated = nr_manifest::schema::manifest_schema_json();
    let path = concat!(env!("CARGO_MANIFEST_DIR"), "/../../schemas/manifest.schema.json");
    if std::env::var("UPDATE_SCHEMAS").is_ok() {
        std::fs::write(path, &generated).unwrap();
    }
    let committed = std::fs::read_to_string(path).unwrap();
    assert_eq!(
        generated, committed,
        "schemas/manifest.schema.json is stale. Regenerate with: \
         UPDATE_SCHEMAS=1 cargo test -p nr-manifest schema_up_to_date"
    );
}
```

Create the initial file with `UPDATE_SCHEMAS=1 cargo test -p nr-manifest schema_up_to_date`, then
commit it. This is RESEARCH.md pattern 3: the schema is generated, never authored, so D-04's
cross-phase contract cannot drift from the types that Phase 2 and Phase 3 will write against.

published documentation.

## Trust boundaries

| Boundary | Description |
|----------|-------------|
| manifest.json on disk -> the harness | A manifest is untrusted input; it may be hand-edited, reconstructed, or corrupt |
| the D-14 snapshot -> a public git repository | Everything the manifest records becomes public the moment a run is committed |
| ArtifactRecord.path -> the filesystem | A path from a manifest is used to open a file relative to a run directory |

## STRIDE threat register

| Threat ID | Category | Component | Disposition | Mitigation plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-03 | Tampering | validate.rs, checksum.rs | mitigate | Per-file blake3 recorded in the manifest and recomputed on validation; a mismatch is `ChecksumMismatch` naming the path, the recorded hash and the computed hash. Required fields are enforced by the absence of `#[serde(default)]` plus `deny_unknown_fields`, so a manifest missing `host` or `artifacts` fails to deserialise rather than defaulting. |
| T-1-06 | Information disclosure | fields.rs HostInfo, NetworkInfo, KernelInfo | mitigate | `HostInfo` carries `rig_slug` (a chosen label) rather than hostname; `NetworkInfo` has no MAC and no SSID field; no serial number field exists. Task 3 is a blocking human review of the generated schema before any manifest is published, covering `kernel.cmdline` and `tools[].argv` specifically. |
| T-1-07 | Spoofing | checksum.rs | accept | Checksums prove integrity, not authenticity. Signing is out of scope for v1. Mitigated by disclosure: the limitation is stated in the crate doc comment and repeated in `docs/publication-layout.md` (plan 01-09) so no reader can mistake a checksum for a provenance signature. |
| T-1-10 | Repudiation | HarnessInfo | mitigate | Every manifest carries the harness version, the full git SHA and a dirty flag, so a figure can always be tied to the code that produced it. `HarnessInfo` fields are required, so a manifest without them fails to deserialise. |
| T-1-16 | Tampering | ArtifactRecord.path, run_id | mitigate | ASVS V12. `run_id` is validated against `^[a-z0-9][a-z0-9-]{0,63}$` and artifact paths are rejected when absolute or containing a `..` component, before any path is joined to a run directory. |
